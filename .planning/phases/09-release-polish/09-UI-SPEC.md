## Custom Index Contract（OPS-03 自定义首页给页契约）

来源：D-05/D-06/D-07/D-08（锁定）+ embed.go Handler 现状 + headers.go CSP 实证 + sharetoken.go:87-96 委托结构。

**wesh 侧逐字契约（给页通道边界）：**

1. **替换点（唯一）：** embed Handler 装饰一层——「`index.html` 路径（含空路径回落）返回启动读入的自定义字节」；**其他一切路径照旧**走 FileServerFS（dist 仅含内建 index.html，自定义页引用的相对路径资源 → 404）。装饰 embed Handler **一处**，`/` 与 `/s/{token}/` 两通道经 sharePage 既有委托自然统一（D-06 兑现路径——sharetoken.go:91 有效 token 委托 page handler，装饰层在其上游）。
2. **读入语义：** `--index /path/to.html` 启动一次读入 `[]byte` 常驻内存；运行期零磁盘依赖，改文件需重启生效（与 embed 静态伺服同语义）。入 TOML 配置同名键 `index`（P7 D-04 覆盖面先例）。
3. **启动校验（exit 2 fail-fast，parse/validate 分层既定位）：** 不存在 / 不可读 / 非常规文件（目录、设备、socket 等）→ 拒绝；读入字节数 > 上限 → 拒绝。上限默认 **16MiB**（io.LimitReader），TOML 纯配置键 `index-max-size` 可调（**无对应 CLI flag**——P2 D-15 与 D-08 用户裁决的调和形态，README 明示此例外防蔓延）。
4. **gzip：** 启动读入后 **gzip 预压一次缓存**（Claude's Discretion 定稿：采纳预压——16MiB 上限下明文+压缩双份内存可接受；与 embed `.gz` 旁路同语义同 Vary 纪律）：客户端 `Accept-Encoding` 显式含 gzip → `Content-Encoding: gzip` 发预压体；否则明文。`Vary: Accept-Encoding` 恒发（embed.go:36 现状同款，防中间缓存键不完整）。
5. **安全头现状同源（调研实证，契约行）：** securityHeaders 最外层装配不区分内建/自定义页。对自定义页的实际效果：
   - `script-src 'self' 'unsafe-inline'` → **内联脚本可执行**；外部脚本事实上不可行（同源无资源可伺服，跨源被阻断）
   - `style-src 'self' 'unsafe-inline'` → 内联样式可用；外部样式表同上不可行
   - `connect-src 'self'` → 用户页自实现的 WS 终端逻辑**可回连 wesh `/ws`**（同源）——D-05「终端功能由用户页面自行实现，WS 端点照旧暴露」在 CSP 下成立
   - `img-src 'self' data:` → data: URL 图片可用
   - `font-src` 未声明 → 回落 `default-src 'self'` → webfont 不可用（系统字体栈约束同内建页）
   - `frame-ancestors 'none'` → 自定义页不可被 iframe 嵌入（与内建页一致）
   - **推论（README 承诺语素材）：自定义页必须是自包含单 HTML（内联一切脚本/样式/资源）；引用外部 CDN 或相对路径资源必被 CSP/404 阻断。**
6. **其余响应头：** `Content-Type: text/html`（按路径扩展名现状推断）；**不加 `Cache-Control` 新头**（sharePage 注释既定纪律延伸）；base-path 组合下给页路径为 `{bp}/` 与 `{bp}/s/{token}/`（mux 前缀内自然成立）。
7. **wesh 不承担（D-05 直接推论，逐字契约）：** 不注入、不修改、不校验用户 HTML 内容（零模板注入面——拒绝片段注入）；不为自定义页提供任何 UI 组件、文案、设计令牌；自定义页的可访问性、视觉质量、终端逻辑正确性由用户自负。`/api/attach`（ticket 签发）、`/ws`、`/healthz`、`/metrics` 照旧暴露不受 `--index` 影响。

**错误态（启动面，非页面 UI）：** 校验失败 exit 2，错误行**只含路径与系统错误原因类别，绝不含文件内容任何字节**（P3/P4 启动面红线延伸——超限场景尤其不得回显文件内容）。文案机制走 P3 记录式上报既有通道，精确措辞 planner 定。

## D-18 Ship-Clearance Contract（三项 WARNING 清零契约）

来源：07-UI-REVIEW Top 3 Priority Fixes + 07 deferred-items.md 修复指引 + CONTEXT D-18（三项全清——「发布质量门」语义：v1.0.0 发布物无已知 WARNING 挂账）。

### ① 1001 关停面板 hint 条件化（WARNING#1）

- **问题：** systemd `Restart=always` 形态下 wesh ~1s 自重启，「Start wesh again from your shell」为无效指引（用户无需 shell 动作，reload 即唯一正确动作）。
- **定稿（逐字契约）：** `case 1001` 的 hintPrefix 由 `'Start wesh again from your shell, then'` 改为：

  **`'If wesh is not restarted for you, start it again from your shell, then'`**

  渲染：**"If wesh is not restarted for you, start it again from your shell, then [Reload this page]."**
- **两形态真值验证：** 自重启形态——条件句前缀为假时不构成错误指引，reload 链接是唯一所需动作 ✓；非自重启形态——指引精确为真 ✓。条件句式（conditional form）即「按场景条件化」的兑现形态：**静态文案替换，非运行时分支**——前端结构上无法探测 systemd 配置，一条两种部署形态下皆为真的文案是唯一不引入服务端新信号的形态（07-UI-REVIEW 建议原文采纳）。
- **文案单源：** pre-onopen 分派（③）与稳态 `case 1001` 必须经**同一 showStatus 调用形态**（同一字面量/常量单写口）——两处不得各自硬编码（05-08 常量化纪律）。
- **不动项：** title `"Server shutting down"` 与 body `"The wesh server is shutting down. The session has ended."` 逐字不变（07-UI-REVIEW 判定现在进行时为 house-legal，below fix-bar）；动作链接仍为默认 "Reload this page"（07-UI-REVIEW：reload 动作在全部部署形态下正确）。

### ② `#status` 面板族加 `role="alert"`（WARNING#2）

- **定稿（逐字契约）：** `web/index.html:63` `<div id="status" hidden>` → `<div id="status" role="alert" hidden>`——**单属性，零视觉影响，零 CSS 改动**。
- **覆盖面：** `role="alert"` 隐含 `aria-live="assertive"` + `aria-atomic="true"`——hidden 移除时整个面板内容向辅助技术播报；C-1..C-9、1001、Reconnecting 全族一次获得（单容器属性，非逐面板）。
- **已知边界（登记，不改 D-18 裁决）：** Reconnecting 面板正文 1Hz 倒计时更新在 assertive 语义下可能触发屏幕阅读器每秒重播。接受理由：D-18 已裁决单属性最小修复；重连进展本身是用户需要知晓的状态；真实 AT 栈行为按项目分层测试策略属平台原生豁免面（§UI Considerations backstop 行）。若发布后获真实 AT 噪音反馈，再评估 Reconnecting 倒计时节点拆分 live region（v2 候选，非本 phase 范围）。

### ③ pre-onopen 到达的 1001 落专版面板（WARNING#3）

- **问题：** WS 握手未完成（`!opened`）时服务端优雅关停，落 C-4「Unable to connect / refusing new connections」文案——误述关停为拒绝服务（毫秒级窗口，WARNING-low）。
- **定稿（逐字契约）：** onclose 分派顺序修订——`if (!opened)` 分支**之前**先分派 `ev.code === 1001` → 落与稳态 `case 1001` **完全相同**的 showStatus 调用（title/body/hint 同源，①的单写口纪律）；其余 `!opened` 路径逐字不变。
- **语义说明：** pre-onopen 客户端从未建立会话，body「The session has ended」对该客户端轻微误述——接受（07-UI-REVIEW 原判：窗口毫秒级、benign；且服务端会话确实已终结，方向正确）。零新文案。
- **不触发重连不变：** pre-onopen 1001 与稳态 1001 同样不在 CORE-05 触发集（仅 1006——07-05 既定回归锁 D11b 不受本修订影响）。
