> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Reconnect Dispatch Contract（重连分派契约）

来源：D-01/D-02/D-04（锁定）+ 06-RESEARCH Pattern 6（状态机形态）+ 06-RESEARCH Pitfall 5/6/7（单例门闩/代际守卫/面板覆盖）。

- **触发谓词（逐字契约）**：`ev.code === 1006` **显式判定**——不是 onclose default 桶。default 桶残留（1002 协议错误等带码关闭）维持 05-UI-SPEC C-5「Connection lost」手动面板**不变**（RESEARCH Anti-Pattern：default 整体转重连会把确定性协议失败卷入重试循环）。
- **不自动重连集合（逐字契约）**：1000/1008/1009/1011 各专版面板不变；**1013 维持 P5 D-10 手动刷新**（被踢端消费跟不上，自动重连只会再被踢且后台标签页循环放大流量——D-01 确认保持）。
- **重连循环（单例）**：onclose(1006) / window `offline` / window `online` 三触发源全部经「已在循环则幂等返回」入口（Pitfall 5：断网瞬间 offline + onclose 相继到达不得启双循环）。`online` 立即试一次 = 清当前等待定时器立即 attempt，**不是**新循环。
- **退避序列**：第 1 次重试等待 1s，其后 ×2（2s/4s/8s/16s），封顶 30s，**无限重试**（D-02）；退避纯函数建议落 `web/src/lib/reconnect.ts`（`backoffMs(attempt) = Math.min(1000 * 2 ** attempt, 30000)`，node --test 单测——prefs.ts/title.ts 先例）。
- **「Reconnect now」手动入口**：点击即清当前等待定时器并立即发起 attempt（ROADMAP「手动入口」落此）；循环**不终止**——若本次 attempt 失败，按退避序列继续。
- **循环终止条件（终态分派，逐字契约）**：

  | 事件 | 处置 |
  |------|------|
  | fetch 响应 401/404/429/503 | 落 05-UI-SPEC 响应分派矩阵对应专版面板（C-3/C-2/认证两态/404 探测直连），**循环终止** |
  | fetch throw（网络不可达/服务端已退出不可区分，D-11） | 留在循环，Reconnecting 面板持续 |
  | WS onclose code === 1006 | 留在循环 |
  | WS onclose 其他码 | 落既有面板分支，**循环终止** |
  | WELCOME 到达 | 重连成功（§Reconnect Success Contract），循环退出，退避清零 |

- **重连中面板保护（Pitfall 7，逐字契约）**：循环驱动的 attempt 失败**只更新 Reconnecting 面板计数**，connect() 既有 catch / onerror-!opened 的「Unable to connect」面板**不得覆盖** Reconnecting 面板——专版面板仅上表终态分支允许显示。connect() 承载重连上下文（参数或面板抑制回调，实现形态 planner 定）。
- **代际守卫（Pitfall 6，本 phase 新必要件）**：重连首次引入「旧 socket 未死透 + 新 socket 已建立」双连接窗口——每个 handler 入口 `if (sock !== ws) return;`（main.ts:476 `const sock = ws` 闭包先例天然承载）；onclose 的 beforeunload 移除同样需代际判定（stale socket 不得拆新连接刚注册的监听）。
- **认证不绕行**：每次 attempt 走完整 connect() 重入链（fetch ticket → Hello 核销）；凭据模式浏览器 Basic 缓存凭据随同源 fetch 自动附带（P3 A2 假设已 UAT 验证）；share token URL 保留（05 红线）使分享链接进入的页面重连链路不变。

## Reconnect Panel Contract（Reconnecting 面板契约）

来源：D-03（复用 showStatus 三态）+ D-11（hint 文案）+ OQ2（showStatus 参数化，本契约定稿）。

- **结构**：复用 `#status` 全屏三态面板，DOM/CSS 零改动（标题/正文/提示行三节点既有）。
- **showStatus 参数化（R3，逐字契约）**：hint 动作链接由硬编码「Reload this page + location.reload()」改为**可选动作参数**（label + onClick）；**缺省保持 Reload 现状零漂移**——全部既有调用点（C-1..C-8 各面板）渲染逐字节不变。Reconnecting 面板传入 label "Reconnect now" 与跳过等待回调。
- **正文两态（1Hz 更新）**：等待期显示倒计时（attempt N + 剩余秒数）；attempt 在途（定时器触发或手动点击后 connect() 飞行中）显示「Retrying now」。更新只写既有节点的 textContent（showStatus 幂等形态同款），面板不闪隐。
- **attempt 计数语义**：首次自动重试 = attempt 1（等待 1s）；初始连接不算 attempt；WELCOME 到达后计数清零。
- **提示行**：hintPrefix 明示服务端已退出场景（D-11），渲染形态「{hintPrefix} [Reconnect now].」与既有面板「{hintPrefix} [Reload this page].」同构。
- **面板期间输入**：ws.readyState 门控既有（INPUT 仅 OPEN 时发送）——重连等待/在途期间键盘敲击静默丢弃，零新逻辑。

## Session Ended Contract（EXIT 帧承接契约）

来源：D-08/D-09/D-10（锁定）+ 06-RESEARCH Pattern 3（退出码/信号提取）/ Pitfall 3（信号名形态）。

- **前端承接（逐字契约）**：onmessage switch 新增 `case EXIT (0x58)`——JSON.parse 载荷暂存 `lastExit`（lastError 同款通道同款容错：parse 失败 console.warn 静默丢弃）；onclose `case 1000` 正文 = `lastExit?.message ?? 既有硬编码文案`（旧服务端/异常路径回退，前向兼容 P2 D-02）。
- **message 服务端组文案唯一写口（D-09）**：前端不自维护信号文案表、不改写、不拼接——textContent 直显（showStatus 全程无 innerHTML，注入面结构性不存在）。文案形态（本契约定稿，英文）：

  | 场景 | exit_code | message |
  |------|-----------|---------|
  | 正常退出（含 exit 0） | N | `The process exited with code {N}.` |
  | 信号死亡 | -1 | `The process was killed by signal {SIGNAME}.`（SIGNAME = 约定大写名 SIGHUP/SIGINT/SIGKILL/SIGTERM 等；未知名 → `signal {number}`） |
  | 非 ExitError 兜底 | -1 | `The process terminated.` |

  - **Pitfall 3 红线**：`Signal.String()` 产出小写描述词（"hangup"）——SIGNAME 须显式映射，不得裸用 String()。
- **面板其余两元素不变**：title 恒 "Session ended"；hint 恒 "Start wesh again from your shell, then [Reload this page]."（C-7 结构不变——wesh 随子进程退出而停止，提示精确为真）。
- **--once/--exit-when-empty 收口路径同帧**：SIGHUP 致死 → 客户端收到 "killed by signal SIGHUP" 形态 message + 1000——与自然退出同一面板通道，零特判。
- **EXIT 帧无 ro/rw 分档**：全员同帧（终结无权限语义，05 既定）；前端 ro/rw 两态渲染路径相同。

## Reconnect Success Contract（重连成功首屏契约）

来源：D-05（清屏 + SIGWINCH）+ P4 D-18（beforeunload 重注册先例）+ P5 D-12（标题自然恢复先例）。

- **WELCOME 到达即（逐字契约）**：退避清零 → 隐藏状态面板 → `term.clear()` 清屏 → 既有 WELCOME 处理链照常（sessionDims/isRO/prefs/refit/welcomeDone 逐字既有）→ beforeunload 按开关重注册（main.ts:635-637 先例）。
- **清屏不保留旧 buffer（D-05）**：重连窗口期错过的输出形成断层，增量重绘有 G-05-1 同类花屏风险——`term.clear()` 后由服务端 attach 路径既有 SIGWINCH（server.go:752，每 attach 恒触发）强制全屏程序秒级重绘；行内 shell 历史交 tmux/herdr（README 文档职责，非 UI）。
- **重连后身份信号零新 UI（D-06）**：ro/rw 由新 WELCOME 重新驱动——`[ro] ` 标题前缀/disableStdin/ro 一次性 console 提示全部经既有路径自然重应用；owner 重连不恢复写权限的 UI 表达 = 既有 `[ro] ` 前缀出现，无新文案、无通知组件。
- **标题**：清屏后标题保持最后 remoteTitle 直到下次 OSC 2/重绘（P5 D-12 先例）；不主动重置。
