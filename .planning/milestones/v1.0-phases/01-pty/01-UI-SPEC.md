# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase 1 UI 形态说明（先于一切表格）：** 本 phase 的前端是**单页、单终端、全视口零铬**（zero-chrome full-bleed）：整个 UI 表面 = 一个 `<div id="terminal">`（托管 xterm.js）+ 一个默认隐藏的 `#status` 状态面板（WS 连接失败/断开时显示）。**无** dashboard、tabs、sidebar、设置面板、按钮、表单——这些在 v1 全部 Out of Scope（REQUIREMENTS.md "多会话管理 UI" 明确排除）。因此本契约的核心是 §Terminal Options Contract（xterm.js 构造选项即视觉契约），传统页面排版契约仅作用于状态面板。

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none |
| Icon library | none（本 phase 零图标） |
| Font | 终端：系统等宽字体栈（见下）；状态面板：系统 sans 栈 |

**shadcn gate 结论：** 不初始化。锁定技术栈（CONTEXT.md D-13）为 Vite 8 + vanilla TypeScript + xterm.js，**无 React**——shadcn 是 React 组件库，对本 phase 结构上不适用。且 vite-plugin-singlefile 要求全部资源 inline 进单 HTML（D-18），引入组件框架与之背道而驰。注册表安全门：不适用（无任何 registry/block）。

**字体加载策略（singlefile 硬约束推导）：** 禁用一切 webfont/外部字体请求——单 HTML 须离线可用、go:embed 内嵌、零运行时网络依赖（RESEARCH.md §Standard Stack + phase_context 明示）。终端字体使用系统等宽栈：

```
Menlo, Monaco, "Cascadia Mono", Consolas, "DejaVu Sans Mono", "Liberation Mono", "Courier New", monospace
```

（macOS 取 Menlo、Windows 取 Cascadia/Consolas、Linux 取 DejaVu/Liberation——各平台取hinting 最优的系统自带等宽字体；CJK 字形由 OS 字体回退自动覆盖，Phase 4 FE-02 再评估。）状态面板 sans 栈：`system-ui, -apple-system, "Segoe UI", Roboto, sans-serif`。

|------|------|--------|-------------|

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#000000` | 页面 `<html>/<body>` 背景 + 终端背景（同一色，防白闪） |
| Secondary (30%) | `#161616` | 状态面板表面（border: 1px `#2a2a2a`） |
| Accent (10%) | `#729fcf` | **仅** 状态面板内 "Reload this page" 链接文字 |
| Destructive | not applicable | 本 phase 无任何破坏性操作 |

Accent reserved for: 状态面板 "Reload this page" 链接文字。**全 phase 唯一 accent 使用点**——无按钮、无 badge、无其他交互铬。取色与终端 ANSI brightBlue `#729fcf` 同色，保持单一调色板内聚。

**文字色（补充声明）：** 主文字 `#ffffff`（终端前景 + 面板标题）；次文字 `#a3a3a3`（面板正文/提示行）；面板遮罩 `rgba(0,0,0,0.6)`（终端最终输出在遮罩下仍隐约可读）。

**无白闪契约：** `<body>` 背景色由 inline CSS 在 `<head>` 声明（vite-plugin-singlefile 保证 CSS 先于 JS 内联），JS bundle 加载/xterm 初始化完成前视口即为纯黑——与终端背景同色，消除 FOUC/白闪。

## Terminal Options Contract (xterm.js)

> 本 phase 的核心视觉契约。`new Terminal(options)` 的构造选项即设计规范，executor 逐项照抄，不得依赖库默认值（显式钉死，防上游默认漂移）。

| Option | Value | 来源 / 理由 |
|--------|-------|------------|
| `fontSize` | `14` | RESEARCH.md Pattern 5（已锁定） |
| `fontFamily` | 上述等宽栈原文 | 见 §Design System 字体策略 |
| `lineHeight` | `1.0` | 终端网格渲染标准值 |
| `letterSpacing` | `0` | 默认；等宽网格不扩字距 |
| `fontWeight` | `400` / `fontWeightBold: 700` | 常规/ANSI 加粗 |
| `cursorStyle` | `'block'` | 经典终端光标形态 |
| `cursorBlink` | `true` | **有意覆盖 xterm.js 默认 false**——主流终端模拟器（GNOME Terminal/iTerm）默认闪烁，闪烁光标是输入点的关键可见性提示；Phase 4 FE-07 可配化 |

| `allowTransparency` | `false` | 不透明纯黑底，与页面背景契约一致 |
| `theme` | 下表完整钉死 | 见 §Terminal Theme |

## Page Shell & Layout Contract

```css
/* index.html <head> 内联（singlefile 保证先于 JS 生效）——契约级，逐字实现 */
html, body { margin: 0; padding: 0; height: 100%; background: #000000; overflow: hidden; }
#terminal { width: 100%; height: 100%; }
```

- `<title>wesh</title>`（动态标题同步是 Phase 4 CORE-03，本 phase 静态）。
- `<meta name="viewport" content="width=device-width, initial-scale=1">`（标准值；移动端专项 UI 不在本 phase 范围）。
- 页面仅两个顶层元素：`#terminal`（始终存在）与 `#status`（默认 `hidden`）。
- **无加载 spinner**：WS 连接窗口期呈现的是"已打开的空黑终端"（Pattern 5：`term.open()` 同步执行于 WS 连接之前），终端本身就是加载态。黑底无白闪契约见 §Color。

### 状态面板（#status）布局契约

- 触发：`ws.onerror` / `ws.onclose`（任意关闭路径）时移除 `hidden`；本 phase 无重连（CONTEXT.md D-10/D-11：任意终结路径服务端整体退出），面板为终态展示。
- 结构：`position: fixed; inset: 0` 全屏遮罩（`rgba(0,0,0,0.6)`），flex 居中一个 `max-width: 480px; padding: 24px; border-radius: 8px; background: #161616; border: 1px solid #2a2a2a` 面板。
- 面板内三行：标题（Status heading）→ 正文（Status body，间距 8px）→ 提示行（Status hint，间距 16px，内含 accent 色 "Reload this page" 链接，`<a href="">` 原地刷新）。
- 面板显示期间终端内容保持在原位（遮罩下隐约可读最终输出）；键盘输入已被 `ws.readyState === OPEN` 门控丢弃（Pattern 5 已有），无需额外遮罩拦截。

## Renderer Contract (FE-01)

- 首选 WebGL 渲染器：`term.loadAddon(new WebglAddon())` 以 try/catch 包裹，异常时停留在 DOM 渲染器（xterm.js 6 已删除 canvas 渲染器，回落目标唯一）。
- **注册 `webglAddon.onContextLoss(() => webglAddon.dispose())`**：GPU 上下文丢失（驱动重置/睡眠唤醒）时自动回落 DOM，不黑屏卡死。（官方 demo 同款模式，RESEARCH.md §Pattern 5 引用。）
- 渲染器选择对用户不可见——无提示、无 badge。

## Interaction Contract

- **启动聚焦：** `ws.onopen` 内 `fit.fit(); sendResize(...); term.focus()`（Pattern 5）——页面打开即键盘可用，无需先点击。
- **resize 回路（FE-03/CORE-02）：** window resize → 100ms debounce → `fit()` → `onResize` → RESIZE 帧；发送前 `Number.isInteger && > 0` 防护（RESEARCH.md Pitfall 2 防抖/NaN 防护，已锁定，此处仅登记交互语义：拖动窗口期间终端内容随行列变化实时重排，无浮层、无尺寸指示器——COLSxROWS 浮层是 Phase 4 FE-06）。
- **键盘输入门控：** 仅 `ws.readyState === OPEN` 时发送 INPUT 帧；关闭后面板显示期间输入静默丢弃。
- **滚动：** xterm 原生滚动条，scrollback 10000 行；长行按 cols 折行（标准终端行为，resize 后由远端程序经 SIGWINCH 重绘）。
- **本 phase 明确没有的交互：** 无右键菜单、无选中复制增强（Phase 4 FE-05）、无超链接点击（Phase 4 FE-04）、无离开确认（Phase 4 FE-06）、无重连按钮（Phase 6 CORE-05）。

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | none（本 phase 无交互铬；唯一链接为状态面板内 "Reload this page"） |
| Empty state heading | not applicable——无数据集合；"空终端"即加载态（见 §UI Considerations） |
| Empty state body | not applicable（同上） |
| Error state: 连接失败（onerror / 握手被拒，含第二客户端 409 场景） | **"Unable to connect"** / "The wesh server is unreachable. It may have exited, or another client is already attached (wesh currently allows a single client)." / 提示行: "Check the shell where wesh is running, then [Reload this page]." |
| Error state: 正常关闭 1000（子进程退出，CONTEXT D-10） | **"Session ended"** / "The process exited and the wesh server has stopped." / 提示行: "Start wesh again from your shell, then [Reload this page]." |
| Error state: 异常断开（非 1000 关闭） | **"Connection lost"** / "The connection closed unexpectedly. In this phase the server exits when the connection drops." / 提示行: "Start wesh again from your shell, then [Reload this page]." |
| Destructive confirmation | not applicable——本 phase 无破坏性操作 |

文案语言为英文（CLI 工具惯例，与 GoTTY/ttyd 一致）；方括号部分为 accent 色链接。三条文案区分 `ev.code === 1000` 与否 + 是否曾成功 `onopen`：未 open 过 → 连接失败；open 后 1000 → Session ended；open 后非 1000 → Connection lost。
